# Справочники (Guide) и IndexedDB

При первом заходе в приложение создаётся IndexedDB с именем из `package.json` (поле `name`). В ней
создаются объектные хранилища (таблицы) для справочников и заполняются данными из JSON-файлов в
`src/assets/guide/` с префиксом `guide-`. Пока идёт инициализация, показывается экран splash; после
завершения отображается либо экран авторизации, либо home (в зависимости от сессии).

## Версионирование БД

Версия БД задаётся константой `DB_VERSION` в `src/shared/libs/indexedDb/types.ts`. При увеличении
версии браузер вызывает `onUpgradeNeeded`: все старые хранилища удаляются, создаются заново (
пустые), затем выполняется заполнение из JSON. Таким образом, при смене версии таблицы и данные
пересоздаются.

---

## Как добавить новый справочник

1. **Добавить JSON-файл** в `src/assets/guide/`, имя с префиксом `guide-`, например:  
   `guide-cities.json`.  
   Каждая запись в JSON должна содержать поле **`id`** (число) — оно используется как keyPath в
   IndexedDB.

2. **Зарегистрировать store в entities/guide**  
   В `src/entities/guide/model/types.ts`:

- Добавить имя store в массив `GUIDE_STORE_NAMES`, например:  
  `['continents', 'countries', 'regions', 'cities']`
- Добавить запись в `GUIDE_JSON_FILES`:  
  `cities: 'guide-cities.json'`

3. **Подключить данные в app/init**  
   В `src/app/init/initGuideDb.ts`:

- Добавить импорт:  
  `import citiesData from '@assets/guide/guide-cities.json'`
- Добавить в объект `GUIDE_DATA`:  
  `cities: citiesData as GuideRecord[]`

После этого при первом запуске (или после повышения `DB_VERSION`) будет создано хранилище `cities` и
заполнено из JSON.

## Для чего функция `deleteDb`?

`deleteDb(name: string)` из `@shared/libs/indexedDb` полностью удаляет базу IndexedDB с указанным
именем. Сейчас она **не вызывается** в коде инициализации справочников.

Она нужна для сценариев, когда нужно принудительно сбросить БД (например, «Очистить данные
приложения» в настройках, отладка, смена схемы без повышения версии). Перед вызовом нужно закрыть
все соединения с этой БД; иначе сработает событие `onblocked`. После удаления при следующем открытии
БД будет создана заново с актуальной версией и заполнена из JSON.

---

## Для чего `GUIDE_JSON_FILES`?

`GUIDE_JSON_FILES` в `src/entities/guide/model/types.ts` — это **маппинг «имя store → имя
JSON-файла»** (без пути). Он задаёт соответствие между объектным хранилищем в IndexedDB и файлом с
исходными данными для первичной загрузки.

Сейчас в `initGuideDb` данные подключаются через статические импорты и объект `GUIDE_DATA`, а не
через `GUIDE_JSON_FILES`. Константа используется как:

- **Единый справочник** — по коду видно, какой store из какого файла заполняется.
- **Основа для расширения** — при переходе на динамическую загрузку (например, `import()` по имени
  файла) или для генерации списка файлов в скриптах/документации можно опираться на
  `GUIDE_JSON_FILES`.

Если добавите новый справочник, в `GUIDE_JSON_FILES` нужно добавить соответствующую запись, чтобы
маппинг оставался полным и предсказуемым.

## Удобное использование IDB в коде

- **Хук `useAppDb()`** (`@shared/hooks/useAppDb`) возвращает `{ dbName, version }` — имя БД из
  `package.json` и текущую `DB_VERSION`. Используйте в компонентах, чтобы не повторять эти значения
  в
  каждом вызове.

- **`runWithDb(options, fn)`** (`@shared/libs/indexedDb`) открывает БД, выполняет `fn(db)` и в
  `finally` закрывает соединение. Подходит для разовых операций (чтение, запись, очистка) без
  ручного `openDb`/`close`.

- **Обобщённые операции**: вместо функций, завязанных на конкретные таблицы (например `user`/
  `visits`), в коде используются `writeToStores(options, data)`, `clearStoresList(options,
  storeNames)` и т.п. Список store сессии вынесен в константу `SESSION_STORE_NAMES` в
  `entities/session`; при добавлении новых таблиц достаточно расширить этот массив и передавать
  данные в общие функции.
