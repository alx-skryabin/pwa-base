# Автоматический подъём версии и теги релизов

При успешном попадании кода в ветку `master` (прямой push или мерж pull request) версия в
`package.json` увеличивается автоматически, создаётся коммит с новой версией и теги.

## Когда это срабатывает

1. В ветку `master` делают **push** (или мержат **pull request**).
2. Запускается workflow **«Lint & Prettier»** (проверка линтера и Prettier).
3. Если CI завершился **успешно**, запускается workflow **«Release version bump»**.
4. Workflow проверяет, что последний коммит на `master` — **не** служебный релизный (сообщение не
   начинается с `release: `).
5. Если это обычный коммит:
  - увеличивается **patch**-версия в `package.json` (например, `0.0.1` → `0.0.2`);
  - создаётся коммит с сообщением вида **`release: 0.0.2 [skip ci]`**;
  - к этому коммиту крепятся теги:
    - **`v0.0.2`** (аннотированный тег с версией, остаётся в истории);
    - **`release`** (всегда указывает на последний такой коммит, при каждом новом релизе
      обновляется);
  - коммит и теги **пушатся** в тот же репозиторий.

В итоге: только при **успешном** прохождении lint и Prettier на `master` создаётся релизный коммит и
теги. Коммит с сообщением `release: ... [skip ci]` не запускает CI повторно.

## Что видно в репозитории

- В истории `master`: обычные коммиты и коммиты вида **`release: 0.0.2 [skip ci]`**.
- Теги:
  - **`v0.0.1`**, **`v0.0.2`**, **`v0.0.3`** … — по одному на каждый релиз;
  - **`release`** — всегда указывает на последний релизный коммит (удобно для «последняя стабильная
    версия»).

## Где настроено

- Workflow: [.github/workflows/release-bump.yml](../.github/workflows/release-bump.yml)
- Зависимость от CI: запуск по событию **workflow_run** после успешного завершения **«Lint &
  Prettier»** на ветке `master`.

## Увеличение minor/major

Сейчас используется только **patch** (`npm version patch`). Чтобы поднимать **minor** или **major**
по условию (например, по меткам в коммите или по веткам), можно доработать шаг «Bump version»
в [release-bump.yml](../.github/workflows/release-bump.yml) (например, вызывать `npm version minor`
или `npm version major` при определённых условиях).
