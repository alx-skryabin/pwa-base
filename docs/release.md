# Автоматический подъём версии и теги релизов (локально.)

---

Можно использовать также GitHub Actions для выполнения через GitHub

При успешном коммите в ветку `master` (прямой коммит или результат мержа другой ветки) версия в
`package.json` увеличивается автоматически, создаётся коммит с новой версией, теги и всё пушится в
`master`. Вся логика выполняется **локально** через Git Hooks (Husky).

## Когда это срабатывает

1. Вы делаете **коммит в ветку master** (или мержите в master и делаете merge-коммит).
2. Срабатывает **pre-commit** (Husky + lint-staged): проверка ESLint и Prettier по staged-файлам.
   Коммит не создаётся при ошибках или предупреждениях.
3. После **успешного** коммита срабатывает **post-commit** (Husky): скрипт
   `scripts/release-bump.cjs`.
4. Скрипт проверяет: текущая ветка — `master`, сообщение последнего коммита **не** начинается с
   `release: `.
5. Если условия выполнены:

- увеличивается **patch**-версия в `package.json` (например, `0.0.1` → `0.0.2`);
- создаётся коммит с сообщением **`release: 0.0.2`**;
- к этому коммиту крепятся теги:
  - **`v0.0.2`** (аннотированный тег с версией, остаётся в истории);
  - **`release`** (всегда указывает на последний такой коммит, при каждом новом релизе
    обновляется);
- коммит и теги **пушатся** в `origin master`.

В итоге: только при **успешном** прохождении lint и Prettier в pre-commit на master создаётся
релизный коммит и теги, всё выполняется на вашей машине.

## Что видно в репозитории

- В истории `master`: обычные коммиты и коммиты вида **`release: 0.0.2`**.
- Теги:
  - **`v0.0.1`**, **`v0.0.2`**, **`v0.0.3`** … — по одному на каждый релиз;
  - **`release`** — всегда указывает на последний релизный коммит.

## Где настроено

- **post-commit** хук: [.husky/post-commit](../.husky/post-commit) — вызывает
  `node scripts/release-bump.cjs`.
- Скрипт: [scripts/release-bump.cjs](../scripts/release-bump.cjs) — проверка ветки и последнего
  коммита, bump, коммит, теги, push.

## Новый пользователь

После `git clone` и `npm install` хуки устанавливаются автоматически (`prepare` → `husky`).
Дополнительно настраивать ничего не нужно: коммиты в любую ветку проверяются pre-commit (lint +
prettier), коммиты в master дополнительно запускают release-bump в post-commit.

## Увеличение minor/major

Сейчас используется только **patch** (`npm version patch`). Чтобы поднимать **minor** или
**major**, измените в [scripts/release-bump.cjs](../scripts/release-bump.cjs) вызов на
`npm version minor` или `npm version major`.
